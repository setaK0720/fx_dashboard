# 注文機能 実装計画

## 目標
フロントエンドから新規注文（成行）を発注し、バックエンドでそれを受け付けて処理（シミュレーション）する機能を実装します。

## 提案内容

### 1. バックエンド (FastAPI)
- **APIエンドポイント**: `POST /api/orders`
    - リクエストボディ: `symbol` (str), `order_type` (str: "BUY"|"SELL"), `volume` (float)
    - レスポンス: `order_id`, `status`
- **ロジック**:
    - 注文を受け取り、ログに出力（今回はシミュレーションなので実際のブローカーAPIは呼ばない）。
    - 成功としてレスポンスを返す。
    - (オプション) `positions` テーブルにダミーデータを追加して、即座にポジション一覧に反映させる。

### 2. フロントエンド (React)
- **コンポーネント**: `OrderForm`
    - 通貨ペア選択 (ドロップダウン)
    - 売買区分選択 (ラジオボタン or ボタン)
    - 数量入力 (数値入力)
    - 注文ボタン
- **バリデーション**:
    - 数量が正の数であること。
- **フィードバック**:
    - 注文成功時にToast通知を表示。
    - エラー時にエラーメッセージを表示。

## 検証計画
1.  **APIテスト**: Swagger UIから `POST /api/orders` を実行し、200 OKが返ることを確認。
2.  **UI動作**: フォームに入力して注文ボタンを押し、成功通知が表示されることを確認。
3.  **データ反映**: 注文後、ポジション一覧に新しいポジションが追加されることを確認（バックエンドで追加ロジックを実装する場合）。
